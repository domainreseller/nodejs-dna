# nodejs-dna — REST+SOAP Modernization Design

**Date:** 2026-07-01
**Status:** Approved (design), pending implementation plan
**Reference implementation:** `php-dna` (`DomainNameApi/` — Facade + DNARest + DNASoap + SharedApiConfigAndUtilsTrait)

## 1. Goal

Bring the `nodejs-dna` library to full parity with the `php-dna` dual-transport
architecture, rebuilt "the modern way":

- **Dual transport** with automatic routing: UUID username → REST, normal
  username → SOAP (mirrors the php-dna facade).
- **TypeScript + ESM**, published with dual ESM/CJS output and generated `.d.ts`.
- **Modern, breaking public API (v3)**: camelCase methods, typed result objects,
  exceptions on error (no `{result, data}` envelope).
- **Full method parity** plus the recent php-dna behavioral fixes.

### Current state (baseline)

- Single `index.js` (~900 lines), CommonJS, **SOAP-only** (`strong-soap` + `axios`).
- `class DomainNameAPI`, ~20 PascalCase methods, `{result, data}` return envelope.
- Version mismatch: class `VERSION = '2.0.14'`, `package.json` `1.0.3`.
- Published to npm via `.github/workflows/npm-publish.yml` (on release → `npm publish`).
- SOAP endpoint: `https://whmcs.domainnameapi.com/DomainApi.svc?singlewsdl`.
- No REST, no shared layer, no types.

### Locked decisions

| Decision | Choice |
|---|---|
| Stack | TypeScript + ESM, dual CJS output |
| Public API | Modern breaking v3 (camelCase, typed results, exceptions) |
| Scope | Full parity: architecture + all methods + behavioral fixes |
| Architecture | **Approach A** — mirror php-dna structure, modernized internals |
| REST HTTP | Native `fetch` (Node 20+), drop `axios` |
| SOAP | Keep `strong-soap`, wrapped behind `SoapClient` (swappable) |
| Telemetry | Sentry parity, lightweight native-fetch envelope, default ON, opt-out |
| Version | `3.0.0` (clean reset from 2.0.14/1.0.3 mismatch) |
| Test style | Runnable sequential example scripts against OTE (not assertion-framework-heavy) |

## 2. Module layout

```
src/
├─ index.ts                 public exports (DomainNameApi + types + errors)
├─ DomainNameApi.ts         FACADE          ← php-dna DomainNameAPI_PHPLibrary.php
├─ clients/
│  ├─ DomainApiClient.ts    shared interface implemented by both clients
│  ├─ RestClient.ts         REST impl       ← php-dna DNARest.php
│  └─ SoapClient.ts         SOAP impl       ← php-dna DNASoap.php
├─ core/                    ← php-dna SharedApiConfigAndUtilsTrait.php, split into focused modules
│  ├─ BaseClient.ts         retry, timeout, error mapping, telemetry, lastRequest/Response
│  ├─ config.ts             URL_PROD/URL_OTE, timeouts, VERSION, application
│  ├─ errors.ts             error hierarchy
│  ├─ telemetry.ts          Sentry envelope reporter
│  └─ normalize.ts          .tr attrs, country ISO, status maps
└─ types/                   DomainDetails, Contact, TldInfo, request/response types
test/                       example-style sequential OTE integration scripts
tsconfig.json, tsup.config.ts
package.json                type: module + dual exports map
```

Top-level structure is 1:1 with php-dna so a fix landed in one repo maps to the
same place in the other. The one deliberate improvement: the 912-line shared
trait is decomposed into focused `core/` modules (config, errors, telemetry,
normalize, BaseClient) for testable boundaries.

## 3. Facade, routing, auth

- `new DomainNameApi(userName, password, { testMode?, telemetry?, timeout? })`.
- `looksLikeUuid(userName)` → `RestClient`, else `SoapClient`. Username is
  trimmed first (parity with php-dna: padded UUIDs must still route to REST).
- **REST auth** (no login flow): headers `X-API-KEY: {password}` and
  `__reseller: {userName-UUID}`. Base URL `URL_PROD` or `URL_OTE` (testMode).
- **SOAP auth**: `UserName`/`Password` in the request body.
- The facade exposes explicit typed methods that delegate to the active client
  (replacing php-dna's `__call` magic → real methods give autocomplete + types).

## 4. Type system & public API (modern v3)

- Methods camelCase: `getDetails`, `checkAvailability`, `registerWithContactInfo`,
  `syncFromRegistry`, `transfer`, `cancelTransfer`, `approveTransfer`,
  `rejectTransfer`, `renew`, `getContacts`, `saveContacts`,
  `modifyPrivacyProtection`, `getResellerDetails`, `getCurrentBalance`,
  `getList`, `getTldList`, `addChildNameServer`, `deleteChildNameServer`,
  `modifyChildNameServer`.
- Return typed objects (e.g. `Promise<DomainDetails>`); the `{result, data}`
  envelope is removed.
- All input/output types under `types/`; `.d.ts` generated by the build.

## 5. Error model (exception-based)

`core/errors.ts`:

```
DomainApiError (base: code, gatewayCode, details, transport, requestId)
├─ AuthenticationError     ERR_ACCESS_DENIED, invalid credentials
├─ ValidationError         per-field gateway validation failures
├─ DomainNotFoundError     ERR_DOMAIN_NOT_FOUND
├─ RateLimitError          throttling
├─ TransportError          network / timeout / SOAP connection
└─ ApiError                other gateway errors
```

Failed calls `throw`. **This is where the current WISECP fix maps cleanly**:
`getDetails` on a not-found response throws `DomainNotFoundError`; the library
never interprets "not found" as a transfer. The transfer decision belongs to the
caller (mirrors the resolution shipped in wisecp-dna V2.0.8, php-dna memory
`project_wisecp_sync_not_found_not_transfer`).

## 6. Cross-cutting (BaseClient)

- **Retry**: idempotent calls only, exponential backoff.
- **Timeout**: per-request, configurable (default matches php-dna DEFAULT_TIMEOUT).
- **Error mapping**: gateway/SOAP fault → typed exception.
- **Telemetry**: Sentry envelope via native fetch, default ON, `{ telemetry:false }`
  opt-out. Credential/PII redaction is an accepted risk (php-dna memory
  `feedback_sentry_no_redaction`) — do not add extra redaction.
- **Debug**: `lastRequest`, `lastResponse`, `lastResponseHeaders`, `lastFunction`
  exposed for parity.

## 7. Behavioral fixes to port (parity)

- **.tr TRABIS attribute normalization** — REST-only (Owner/Corporate, CITIZEN
  typo fix, drop legacy names). SOAP keeps legacy names. (php-dna BUG-9628,
  memory `project_tr_trabis_rest_normalization`.)
- **register shallow response** — 5-field DTO; empty DomainName/ID by design
  (memory `project_rest_register_shallow_response`).
- **sync not-found ≠ transfer** — naturally expressed as `DomainNotFoundError`
  from `getDetails`; sync/transfer logic never maps not-found to "transferred".
- **Gateway error normalization** + `.tr` attribute string-coercion (REST-only).

Source of truth for REST paths/schemas: DNA gateway `/swagger/v1/swagger.json`
(memory `reference_dna_swagger`).

## 8. Testing

Respecting the established DNA test style (memory `feedback_test_style`):
runnable **sequential example scripts** under `test/`, hitting the OTE sandbox
(e.g. checkAvailability → register → getDetails → syncFromRegistry → transfer
flow). Vitest may serve as a thin runner, but tests stay example-oriented rather
than assertion-framework-heavy. No live credentials committed; OTE creds via env.

## 9. Build, distribution, versioning

- **`tsup`** dual build → ESM + CJS + `.d.ts`; `package.json` `exports` map.
- **Version `3.0.0`** — resets the class/package mismatch and signals the
  breaking modern rewrite (loosely rhymes with php-dna 3.x).
- Update `.github/workflows/npm-publish.yml` to `npm ci && npm run build` before
  `npm publish`.
- Add `domainreseller/nodejs-dna` as `upstream` (not currently a local remote)
  and push there in addition to `xa81` origin, matching the php-dna fleet model.

## 10. Phasing

1. **Skeleton + core** — structure, `config`, `errors`, `BaseClient`, `telemetry`,
   `types`, facade routing + auth.
2. **RestClient** — all methods + behavioral fixes (priority, modern path).
3. **SoapClient** — all methods via `strong-soap` wrapper, parity with REST.
4. **Test + build + publish** — OTE example tests, dual build, version 3.0.0,
   workflow update, upstream wiring.

## Non-goals

- No backward-compatible PascalCase alias layer (clean v3 break).
- No SOAP library migration in this pass (keep `strong-soap`).
- No unrelated refactoring beyond the shared-layer decomposition above.
